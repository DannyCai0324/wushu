# 任務：為五術知識系統產生「分部位經穴定位圖」

## 背景

有一個單檔 HTML 網站（約 1.7MB，繁體中文，深色主題），醫章底下有「經絡篇」，目前收錄十四經 361 穴的**文字定位**（骨度分寸）與背誦口訣，但**沒有圖**。

先前嘗試過一張「全身剪影＋361 個點」的示意圖，失敗了，原因必須先講清楚，否則你會重蹈覆轍：

> 那張圖畫了人形輪廓，把穴位沿手繪路徑平均分配上去。結果是**點浮在人形上、對不到任何可辨識的位置**，使用者的原話是「太不明確，根本看不懂」。
>
> 教訓：**經穴圖能用的關鍵不是人形，是體表標誌。** 所有穴位定位都是「從某個摸得到的標誌起算幾寸」——腕橫紋、肘橫紋、髕骨底、內外踝尖、臍、乳頭連線、椎骨棘突。圖上如果沒有先畫出這些標誌並標好刻度，點畫得再準也沒有意義。

所以這次的核心要求是：**先畫標誌與刻度，再放穴位。**

## 交付物

一組 **分部位的 SVG 定位圖**，以 vanilla JS 內嵌渲染，最終合併回單一 HTML 檔。

**技術限制（硬性）**
- 純 vanilla JS + inline SVG，**不得**引入任何外部函式庫、CDN、build step、npm 套件。
- **不得**使用 localStorage / sessionStorage 或任何瀏覽器儲存 API。
- 不得使用外部圖片；所有圖形以 SVG 圖元繪製。
- 必須是單一 HTML 檔可直接開啟即運作。

## 骨度分寸：座標換算的依據

這是整份規格的核心。每個面板先定義**標誌錨點**與它們的寸值，穴位座標由「該穴的寸數」在錨點之間**線性內插**求得，**不得**用平均分配或目測。

標準骨度分寸（現行通用值）：

| 部位 | 起訖 | 折量寸數 |
|---|---|---|
| 頭部 | 前髮際 → 後髮際 | 12 |
| 頭部 | 兩額角髮際（頭維）之間 | 9 |
| 頭部 | 兩乳突之間 | 9 |
| 胸腹 | 胸骨上窩（天突）→ 胸劍聯合 | 9 |
| 胸腹 | 胸劍聯合 → 臍中 | 8 |
| 胸腹 | 臍中 → 恥骨聯合上緣 | 5 |
| 胸腹 | 兩乳頭之間 | 8 |
| 背部 | 兩肩胛骨脊柱緣之間 | 6 |
| 上肢 | 腋前（後）紋頭 → 肘橫紋 | 9 |
| 上肢 | 肘橫紋 → 腕橫紋 | 12 |
| 下肢 | 恥骨聯合上緣 → 股骨內上髁上緣 | 18 |
| 下肢 | 脛骨內側髁下緣 → 內踝尖 | 13 |
| 下肢 | 股骨大轉子 → 膕橫紋 | 19 |
| 下肢 | 膕橫紋 → 外踝尖 | 16 |

橫向定位以「前正中線／後正中線旁開 N 寸」表示，胸腹橫向以半胸寬 = 4 寸（兩乳頭間 8 寸的一半）為基準換算。

**實作方式建議**：每個面板定義一組 `anchors`，例如上肢屈側：

```js
'arm-inner': {
  viewBox: [0, 0, 260, 640],
  // 縱軸：寸值 → y 座標（0 寸 = 腕橫紋，12 寸 = 肘橫紋，21 寸 = 腋前紋頭）
  axis: [ {cun: 0,  y: 560, label: '腕橫紋'},
          {cun: 12, y: 300, label: '肘橫紋'},
          {cun: 21, y: 120, label: '腋前紋頭'} ],
  // 橫軸：以肢體寬度百分比定位橈側／中線／尺側
  lanes: { radial: 0.22, mid: 0.5, ulnar: 0.78 }
}
```

穴位以 `{cun, lane}` 描述，渲染時換算成實際座標。定位文字裡的「腕橫紋上 2 寸」直接對應 `cun: 2`。

## 每張圖必須包含

1. **肢體或軀幹輪廓**——簡潔線稿即可，不必寫實，但比例要正確。
2. **標誌線與名稱**——腕橫紋、肘橫紋、腋紋頭、臍、乳頭連線、髕骨底、內外踝尖、各椎骨棘突⋯⋯用虛線橫貫並在旁標名。**這是最重要的一項。**
3. **寸刻度**——沿肢體長軸標出刻度（如每 2 寸一格），讓使用者看圖就知道要量幾寸。
4. **穴位點與穴名**——每個點旁邊直接寫出穴名，**不要**做成「點下去才顯示名字」。代號（如 LU9）以較小字級附在穴名下方或後方。
5. **經脈連線**——同一條經的點依序以細線相連，用該經的顏色。
6. **左右對稱說明**——雙側經脈只畫單側，圖上以文字註明「左右對稱，圖示單側」。

## 互動需求

- 面板上方一列按鈕可切換經脈；選定某經時該經的點與連線高亮、其餘淡化（不要隱藏，保留空間感）。
- 點擊任一穴位，於圖下方顯示：穴名、代號、所屬經脈、完整骨度分寸定位文字。
- 面板本身可切換（頭面／前軀幹／背／上肢屈側⋯⋯）。

## 手機需求

- 圖**不要**等比縮小到手機寬度——縮小後穴名與點會小到無法辨識與點選。
- 作法：容器 `overflow-x: auto`，SVG 保持自然寬度，讓使用者橫向捲動。
- 觸控目標最小 44×44 CSS px：在可見圓點之外疊一個 `fill: transparent` 的較大圓作為 hit area。
- 穴名字級在自然尺寸下不得小於 11px。

## 穴位資料

```json

    "name": "手太陰肺經",
    "points": [
      {"n": 1, "name": "中府", "code": "LU1",
       "loc": "胸前壁外上方，前正中線旁開6寸，平第1肋間隙", "seg": "胸"}
    ]
  }
}
```

十四經與穴數（**必須完全一致，多一個少一個都是錯**）：
LU 11、LI 20、ST 45、SP 21、HT 9、SI 19、BL 67、KI 27、PC 9、TE 23、GB 44、LR 14、CV 24、GV 28，合計 **361**。

`loc` 欄位已含骨度分寸描述，**請解析它來決定座標**，不要另行猜測位置。無法從 `loc` 解析出明確寸數的穴位（多在頭面與手足末端），改以該區域的解剖標誌直接定位，並在程式碼註解標明它是手動定位。

## 驗收條件

實作完成後逐項自我檢查，未通過不得交付：

1. 十四經穴數與上表完全相符，總數 361；序號連續、代號格式 `<經><序號>` 無誤。
2. 每個穴位的座標可回推：由圖上位置量得的寸數，與 `loc` 描述的寸數誤差在 ±0.5 寸內。
3. 每張圖至少有 3 條具名標誌線與一組寸刻度。
4. 每個穴位的名稱在圖上直接可見，無需互動。
5. 390px 寬的視窗下：頁面本身無橫向溢出（`document.documentElement.scrollWidth === 390`），圖在自身容器內橫向捲動，穴名可辨識。
6. 主控台無錯誤，未使用任何外部資源。
7. 隨機抽驗 10 個穴位，其圖上位置與定位文字互相吻合。
